## 0. 开工前先做这一件事（约 30 分钟，可省后面几小时）

写一个 30 行的探针插件，只验证两件事：

```js
// probe/index.js —— 用完即删，不要进正式包
import { appendFileSync, mkdirSync } from 'node:fs'
import { join } from 'node:path'

const probe = (line) => {
  try {
    const dir = join(process.env.DSH_HOME ?? '', 'preset-probe')
    mkdirSync(dir, { recursive: true })
    appendFileSync(join(dir, 'probe.log'), `${new Date().toISOString()}\t${line}\n`)
  } catch { /* 探针绝不能让插件崩 */ }
}

export function apply(ctx) {
  probe('apply-enter')
  ctx.inject(['agentPresets'], (child) => {
    child.on('agent/created', async ({ agent, source }) => {
      const header = agent.session.header
      probe(`created id=${agent.id} source=${source} cwd=${header.cwd} origin=${header.origin ?? '-'}`)
      try {
        await child.agentPresets.select(agent, 'standard')   // 换成你列表里真实存在的 id
        probe('select-ok')
      } catch (error) {
        probe(`select-fail ${error?.code ?? ''} ${error?.message ?? error}`)
      }
    })
  })
  probe('apply-done')
}
```

| 要回答的问题 | 看什么 |
|---|---|
| Q1 `agent/created` 会不会对**新建**会话触发、source 是不是 `startup` | 探针第 2 行起 |
| Q2 在里面 `select` 成不成功 | `select-ok` / `select-fail` |
| Q3 **复用空白会话**时 source 是不是 `resume`、`select` 会不会 `agent-preset/locked` | 再打开同一工作区一次 |

**Q3 的结果直接决定 R1 的实现复杂度**：

- `select-ok` → R1 几乎零成本，同一段代码顺带覆盖；
- `agent-preset/locked` → 说明该空白会话已有 turn 记录，需要改成"在
  `sessions.create` 复用之前清掉该空白会话"或"接受旧空白会话保持原预设"（二选一，
  见 §5 决策点 D1）。

> 别跳过这步直接写插件（《踩坑录》§7.2：先找能二分的实验，再做取证）。

## 2. 分阶段实施

### 阶段 A：Host 纯逻辑（无宿主依赖，可全单测）

**A1** 写 `lib/resolve.js`：

```js
/** @returns {string|undefined} 该工作区配置的 preset id（空串视为未配置） */
export function wantedPreset(map, workspaceId) {
  const v = map[workspaceId]
  return typeof v === 'string' && v !== '' ? v : undefined
}

/** turnBoundary 投影 → 是否仍为"未开始" */
export function isBlankBoundary(boundary) {
  return boundary != null && boundary.lastTurn === 0 && boundary.openTurnStartSeq === null
}
```

**A2** 写 `lib/target.js`（门禁，纯函数）：

```js
/**
 * @param header  session.header（只用 id/cwd/origin/parentSession）
 * @param source  agent/created 的 source
 * @param map     presetByWorkspace
 * @param workspaceId  由调用方用 resolveByPath 得到
 * @returns {null | { workspaceId, presetId }}
 */
export function pickTarget({ header, source, map, workspaceId }) { … }
```

判定顺序照设计方案 §3.2 的 G0–G7，**顺序本身就是优先级**，别打乱：先 `enabled`，
再子代理/分叉，再 cwd，再工作区，再映射，最后才是"跟当前是否相同"。

**A3** 单测 `scripts/resolve-test.mjs`：至少覆盖

- 有映射 / 无映射 / 映射为空串 / 映射到不存在的 id
- `origin === 'subagent'`、`parentSession` 存在 → 都为 `null`
- 无 cwd → `null`
- `source === 'resume'` + 非空白 → `null`；+ 空白 → 命中
- 当前 preset 已等于目标 → `null`

> 为什么先做这个：`lib/index.js` 里 `import` 了 `@deepseek-ai/schemastery` 之后，
> 从工作区跑测试会 `ERR_MODULE_NOT_FOUND`（《踩坑录》§6.1）。纯逻辑抽出来就没有这个问题。

**验收 A**：`node scripts/resolve-test.mjs` 全绿，且**不 import 任何 `@deepseek-ai/*`**。

### 阶段 B：Host 接线（最小可用，无 UI）

**B1** `lib/schema.js`：

```js
import z from '@deepseek-ai/schemastery'
export const Config = z.object({
  enabled: z.boolean().default(true).volatile(),
  presetByWorkspace: z.dict(z.string()).default({}).volatile(),
})
```

**B2** `lib/index.js`：

```js
export const name = 'workspace-preset'
export function apply(ctx) {
  probe('apply-enter')
  ctx.inject(['agentPresets', 'workspaceRegistry', 'sessionProjections'], async (child) => {
    // 服务就绪不一定在 inject 回调时完成，用事件重试（《踩坑录》§1.4）
    child.on('agent/created', async ({ agent, source }) => {
      try { await handle(child, agent, source) } catch (e) { warn(e) }   // 绝不外抛
    })
  })
  probe('apply-done')
}
```

`handle()` 里做：读 `config()`（**每次现读，不缓存**）→ `resolveByPath(cwd)` →
`pickTarget` → 若空则 `return` → `select()`，全程 try/catch。

**B3** 挂进 profile 验证（**不装、直接改 patch 最快**）：

```powershell
$nm = "$env:DSH_HOME\profiles\web\node_modules\dsh-workspace-preset"
New-Item -ItemType Directory -Force "$nm\lib" | Out-Null
Copy-Item lib\*.js "$nm\lib\" -Force
Copy-Item client.js "$nm\" -Force
# 哈希比对：装了到底是不是我改的（《踩坑录》§1.2）
$a=(Get-FileHash lib\index.js -Algorithm MD5).Hash; $b=(Get-FileHash "$nm\lib\index.js" -Algorithm MD5).Hash
$a -eq $b
```

**验收 B**（手工，不需要 UI）：

1. 在 `profiles/web/cordis.patch.yml` 里给本插件加：

   ```yaml
   - id: workspace-preset
     name: file:///D:/.../node_modules/dsh-workspace-preset/lib/index.js
     config:
       enabled: true
       presetByWorkspace:
         "<某 workspaceId>": "<某 preset id>"
   ```

2. 打开该工作区 → **应为该 preset**；打开另一个未配置的工作区 → **应为全局默认**。
3. 把 preset id 改成 `no-such-preset` → 新会话**仍能开**，探针里一条
   `agent-preset/not-found` 警告。这条最重要：**降级不能变成故障**。

### 阶段 C：客户端设置页

**C1** 只读版先上：`settings.section` 注册一个页面，列出工作区 + 当前映射 + preset 名。
**C2** 再改成可写：下拉 → `form.mutate(...)`。

硬约束（《踩坑录》§3.1/§3.2）：

```js
export const inject = ['slots', 'locale', 'configForms', 'remote.agentPresets', 'remote.workspace']
export function apply(ctx) {           // 必须同步，不许出现 await
  const form = ctx.configForms.get(ENTRY_ID)
  ctx.slots.inject('settings.section', () => ctx.slots.register({
    name: 'settings.section', id: ENTRY_ID, order: 60, locale: NS,
    inject: () => ({ hooks: { form }, setPreset: (wsId, id) => setPreset(form, wsId, id) }),
  }, Section))
}
```

- 组件里 `const snapshot = useForm((v) => v)`（`hooks.<name>` → `use<Name>`，唯一受支持的订阅方式）
- 不要 `import` `@deepseek-ai/dsh-client-ui-primitives`（静态 bundle 不允许）
- 颜色只用 `--dsw-alias-*` token

**C3** 写入两种操作：

```js
// 选中某个 preset
form.mutate([{ op: 'set', path: ['presetByWorkspace', wsId], value: presetId }])
// 选"跟随全局默认"
form.mutate([{ op: 'unset', path: ['presetByWorkspace', wsId] }])
```

`mutate` 自带 revision CAS 与重读（`dsh-client-ui-settings` 的 `ConfigFormController.mutate`，
行号见 [取证索引.md](取证索引.md) #31），不要自己管并发。

**验收 C**：

1. 设置页里能把工作区 A 设成 `X`，刷新页面后仍是 `X`（说明落进 profile patch）
2. 切换成"跟随全局默认"后，`cordis.patch.yml` 里那个键消失（不是变成空串）
3. 该工作区下次新建会话为 `X`
4. **打开设置页期间新会话仍能正常收发消息**（回归 §3.1 那个最严重的坑）

### 阶段 D：打磨

- `enabled` 总开关（关掉后行为完全等于宿主原生）
- preset 列表里 `broken !== undefined` 的项灰显 + 原因
- 工作区改名/删除时映射自动失配 → 只在设置页提示"3 条映射失效"，不自动清理

- 探针降级为**只记失败**（《踩坑录》§6.5），成功后不写日志

## 3. 验收清单（发布前逐条打勾）

### 功能

- [ ] 未配置的工作区 → 新会话用全局默认 preset
- [ ] 配置了的工作区 → 新会话用配置的 preset（**首轮工具表**就是目标预设的）
- [ ] 同一工作区第二次进入（复用空白会话）→ 仍为目标 preset（R1）
- [ ] 打开**已有历史**的会话 → preset **不变**（不能被"新会话默认"污染）
- [ ] 分叉会话 / 子代理会话 → 不受影响
- [ ] 配置里写不存在的 preset id → 会话仍能创建，仅告警
- [ ] 配置里写已删除工作区的 id → 无任何行为

### 回归（每条都对应《踩坑录》一个坑）

- [ ] `apply` 里没有任何 `await`（Host 与 Client 两侧）
- [ ] Client `apply` 同步；打开设置页时消息仍能发出（§3.1）
- [ ] 所有 Config 字段 `.volatile()`（§2.2）
- [ ] `cordis.patch.yml` 的 `name` 是 `'./lib/index.js'`（§1.1）
- [ ] 已装副本与工作区源码哈希一致（§1.2）
- [ ] `apply` 首尾有探针，且探针 `try/catch` 包死（§1.3）
- [ ] 纯逻辑测试能从工作区跑通，不依赖 profile 里的包（§6.1）

### 与既有插件共存

- [ ] 同时启用 `dsh-auto-review-custom` 时：新会话 = auto 权限 + 该工作区的 agent preset
- [ ] 关掉 `dsh-auto-review-custom` 后本插件行为不变（无隐性依赖）

## 4. 排查顺序（出问题时照抄《踩坑录》§8，再补本项目特有两条）

```
1. 探针文件：apply 有没有跑？
2. --dump-config：插件条目解析到哪？（name 对不对）
3. 哈希比对：装的是不是我改的？
4. agent/created 探针：source 是什么、cwd 是什么、resolveByPath 拿到哪个 workspace？
5. 最后才看：select 抛的是什么 code（locked / not-found / invalid）
```

本项目特有：

- **"新会话 preset 没变"** → 先看 `cwd` 与 `resolveByPath` 有没有命中。
  常见原因：工作区是软链、`$DSH_HOME` 搬过家导致 path 记录失效、会话是从别处
  分叉来的（`parentSession` 让 G2 直接跳过了）。
- **"设置页改了但下次仍是默认"** → 大概率是 R4：`presetByWorkspace` 的 dict 写入
  被 `isVolatilePath` 拒了。立刻切到设计方案 §4.2 的形态 B（单 JSON 字符串字段）。

## 5. 待你决定的两个点（实现前必须定，我不替你定）

**D1 — 复用空白会话时预设不一致，怎么办？**

| 选项 | 行为 | 代价 |
|---|---|---|
| D1-a | 强行对齐（切到工作区配置的 preset） | 依赖 §0 Q3 的结论；若被 `locked` 则做不到 |
| D1-b | 不动（旧空白会话保留原预设） | 用户会看到"改了设置但没生效"，需要 UI 提示"新工作区或关闭当前空白会话后生效" |
| D1-c | 进入工作区时**丢弃**那 条空白会话，总是新建 | 最符合直觉，但会产生"空白会话垃圾"（当前设计是复用而非新建，正是为了不产生垃圾） |

**D2 — 映射的键用 `WorkspaceId` 还是路径？**

设计方案选了 `WorkspaceId`（§4.3）。代价：工作区被移除再添加后映射失效。
如果你更在意"目录不变就永远生效"，那就得换路径并自己处理 Windows 的
反斜杠/大小写/软链规范化 —— 那部分必须复用 `resolveByPath` 的结论，不能自己写比较。

## 6. 风险与回滚

**回滚路径只有一条，且很干净**：

```yaml
# profiles/web/cordis.patch.yml
- id: workspace-preset
  name: file:///…/lib/index.js
  disabled: true          # ← 一行停用
```

停用后行为**完全等于**宿主原生（本设计不修改任何宿主状态，只在 `agent/created`
里"择机切一次"，且这一步可被 `enabled: false` 短路）。

风险不是"搞坏什么"，而是"改了没生效"——那属于可观测、可调试的失败，
不是数据损坏。
